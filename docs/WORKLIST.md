## 1. 需求与架构理解

P0 必须交付一个可被客户理解和验证的业务闭环，而不是只交付聊天入口。最小闭环为：

1. 用户用自然语言创建巡检订阅。
2. 系统解析为 Plan DSL，做槽位、资源、权限和风险校验。
3. 前端展示计划卡，用户确认后才执行。
4. 订阅创建后可在订阅列表追溯 `plan_id`。
5. 用户可通过对话查询事件和证据。
6. 用户可做统计问数并看到查询口径。
7. 用户可反馈误报，事件状态和 badcase 同步变化。
8. 关键动作进入审计日志。

## 2. 环境与运行约束

### 当前环境结论

当前仓库可使用 Python 标准库直接运行；DeepVision 网络与 OPPO 授权已验证。运行环境未配置 LLM 网关凭证，因此模型适配代码已完成但验收页面使用显式本地降级解析。旧文档任务接口线上 404，写操作保持关闭。

| 约束 | 处理方式 |
|---|---|
| 当前仓库无既有工程 | 新建轻量全栈 MVP |
| 网络受限 | 不依赖外部包，不需要 npm/pip install |
| 需要可运行验证 | Python 标准库 HTTP + SQLite |
| 需要前端体验 | 原生 HTML/CSS/JS 工作台 |
| 需要自动化自测 | `smoke_test.py` 启动临时服务和临时 DB |
