# 门店视觉合规巡检产品方案

| 项目 | 内容 |
|---|---|
| 文档版本 | v1.1 |
| 日期 | 2026-07-10 |
| 适用产品 | 万象 AGI 巡检 / 对话式 AI 巡检助理 |
| 需求来源 | 极狐门店物料与展示合规巡检、OPPO 门店竞品 Logo/宣传物料巡检 |
| 核心原则 | 通用能力、对象灵活配置、不改变当前产品核心架构、减少用户操作路径 |
| 本版更新 | 合并新增场景对意图识别、Plan DSL、Skill 链路、数据模型和验收标准的影响分析 |

## 1. 需求背景

近期连锁门店客户提出了两类相似需求：

1. **极狐**：希望巡检门店内部是否按要求放置指定物体内容，例如统一风格座椅、统一立牌展架、电视是否播放符合要求的广告图片、门店内是否存在其他品牌汽车等。
2. **OPPO**：希望巡检门店内是否存在其他品牌 Logo 或宣传海报。

这两类需求表面上属于不同行业和不同物体，但本质都是：

> 对门店摄像头画面中的“指定对象、指定品牌、指定物料、指定屏幕内容、禁止出现内容”进行视觉合规判断，并输出证据化巡检结果。

因此不建议分别为极狐和 OPPO 做定制能力，而应抽象为一套通用产品能力：

**门店视觉合规巡检。**

## 2. 产品定位

### 2.1 一句话定位

**门店视觉合规巡检是一个可通过对话配置的视觉合规能力，帮助连锁客户检查门店中指定物体是否存在、指定物料是否合规、禁止品牌是否露出、屏幕内容是否符合要求，并输出证据化结果。**

### 2.2 核心价值

1. **通用**：同一套能力可覆盖汽车展厅、手机门店、零售门店、物业空间、校园场景。
2. **灵活**：客户随时可以修改“要看什么对象”和“不允许出现什么对象”，无需重新开发算法或重编工作流。
3. **低操作成本**：客户通过对话或模板配置对象包和规则，不需要理解底层工作流节点。
4. **可审计**：每次判断都绑定截图、检测框、规则、对象包版本和模型版本。
5. **可进化**：误报、漏报、对象样本和客户反馈沉淀为对象库和 badcase，后续持续提升效果。

## 3. 设计原则

### 3.1 解决通用性

将客户需求抽象为四层：

| 层级 | 抽象对象 | 示例 |
|---|---|---|
| 行业场景 | 门店、展厅、柜台、屏幕、海报区 | 汽车展厅、OPPO 门店 |
| 巡检对象 | 椅子、立牌、电视广告、Logo、海报、车辆 | 统一座椅、竞品 Logo |
| 合规规则 | 必须出现、禁止出现、风格匹配、位置匹配、数量匹配 | 必须有指定立牌，不得出现其他品牌 |
| 证据输出 | 截图、框选、置信度、判断依据、事件状态 | 发现竞品 Logo，截图标框 |

平台不关心客户属于哪个行业，而是关心：

1. 看什么对象。
2. 在哪里看。
3. 什么时候看。
4. 怎么判定合规。
5. 如何输出证据。

### 3.2 解决灵活性

用户随时变化想看的对象时，不修改工作流，只更新：

1. **对象包**：新增、删除、替换目标对象或禁用对象。
2. **参考样本**：上传新的图片、Logo、海报、广告截图。
3. **规则模板**：调整必须出现、禁止出现、数量、区域、相似度阈值。
4. **订阅配置**：选择哪些门店、摄像头、时间段生效。

核心设计是：

> 工作流保持稳定，对象和规则参数化。

### 3.3 不改变当前产品核心架构

本能力复用当前产品链路：

```text
对话入口
  -> Plan DSL
  -> 应用订阅
  -> 工作流执行
  -> 结果中心
  -> 反馈/badcase
```

现有能力映射：

| 当前架构 | 本方案使用方式 |
|---|---|
| Chat Portal | 通过自然语言创建视觉合规订阅、修改对象包、查询结果 |
| 意图识别 | 识别视觉合规订阅、对象包变更、参考素材补充、结果查询和统计查询 |
| Plan DSL | 生成“创建/修改视觉合规规则”的结构化计划 |
| 应用广场 | 新增一个通用能力模板：门店视觉合规巡检 |
| 应用编排画布 | 内部高级配置使用，客户默认不需要进入 |
| 应用订阅 | 选择对象包、规则模板、摄像头、布防时间 |
| 工具库节点 | 对象库、品牌库、OCR、Logo 识别、图片相似度、多模态复核 |
| 结果中心 | 输出合规事件、缺失事件、禁止对象事件和证据 |
| 反馈中心 | 误报、漏报、对象样本补充、规则调整 |

### 3.4 减少用户操作路径

用户默认路径：

```text
说出需求
  -> 系统推荐模板
  -> 用户确认/补充对象
  -> 生成订阅
  -> 查看结果
```

不要求客户：

1. 手动拖拽工作流节点。
2. 选择模型类型。
3. 理解 OVD、OCR、多模态模型等技术细节。
4. 逐个摄像头配置复杂规则。

高级用户或内部交付人员才进入对象包管理、规则模板管理和画布调试。

## 4. 产品能力抽象

### 4.1 能力名称

建议能力名称：

**门店视觉合规巡检**

可在不同行业中显示为：

| 行业 | 前台名称 |
|---|---|
| 汽车展厅 | 展厅物料与品牌合规巡检 |
| 手机门店 | 门店品牌露出合规巡检 |
| 零售门店 | 门店陈列与物料合规巡检 |
| 物业/园区 | 公区物品摆放合规巡检 |

底层仍是同一能力。

### 4.2 支持的巡检对象

| 对象类型 | 说明 | 示例 |
|---|---|---|
| 标准物体 | 门店内必须或禁止出现的具体物体 | 椅子、展架、桌牌、车辆 |
| 标准物料 | 按品牌或活动要求摆放的物料 | 立牌、海报、吊旗、台卡 |
| 品牌 Logo | 品牌标识、竞品 Logo | OPPO、vivo、华为、小米、极狐、其他车标 |
| 宣传海报 | 纸质或电子宣传内容 | 竞品海报、活动海报 |
| 屏幕内容 | 电视、LED 屏幕、电子屏播放内容 | 指定广告图片、指定活动画面 |
| 车辆品牌 | 汽车展厅或门店内车辆品牌 | 是否出现其他品牌汽车 |
| 区域陈列 | 指定区域是否存在指定对象 | 接待区是否有统一座椅 |

### 4.3 支持的合规规则

| 规则类型 | 说明 | 示例 |
|---|---|---|
| 必须出现 | 指定对象必须在画面中出现 | 展厅必须有统一立牌 |
| 禁止出现 | 指定对象不得出现 | OPPO 门店不得出现其他品牌 Logo |
| 数量要求 | 对象数量必须满足范围 | 接待区至少 4 把统一座椅 |
| 位置要求 | 对象必须位于指定区域 | 立牌必须在入口附近 |
| 风格匹配 | 物体外观需与参考样式相似 | 座椅需为统一风格 |
| 内容匹配 | 屏幕或海报内容需符合参考素材 | 电视播放指定广告图 |
| 品牌互斥 | 不得出现竞品品牌或非授权品牌 | 店内不得出现其他品牌汽车 |
| 时段要求 | 只在特定时间巡检 | 营业时间内巡检 |
| 置信阈值 | 低置信只进入待确认 | 置信度低于 0.75 不自动告警 |

## 5. 核心产品对象

### 5.1 对象包 Object Pack

对象包是本方案最核心的抽象。

**对象包 = 客户想检查的一组对象、品牌、样本、同义词和匹配策略。**

示例：

| 对象包 | 用途 |
|---|---|
| 极狐展厅标准物料对象包 | 统一座椅、立牌展架、电视广告、其他品牌汽车 |
| OPPO 门店竞品品牌对象包 | 竞品 Logo、竞品宣传海报 |
| 门店消防合规对象包 | 消防通道、灭火器、遮挡物 |

对象包字段：

| 字段 | 说明 |
|---|---|
| object_pack_id | 对象包 ID |
| tenant_id | 租户 |
| name | 对象包名称 |
| industry | 行业标签 |
| scenario | 场景标签，如展厅、门店、柜台 |
| target_objects | 必须检测对象 |
| forbidden_objects | 禁止出现对象 |
| reference_assets | 参考图片、Logo、海报、广告截图 |
| synonyms | 同义词，如立牌/展架/易拉宝 |
| match_policy | 匹配策略 |
| version | 版本 |
| status | 草稿、生效、停用 |
| updated_by | 更新人 |
| updated_at | 更新时间 |

### 5.2 对象定义 Object Definition

对象定义是对象包中的单个对象。

字段：

| 字段 | 说明 |
|---|---|
| object_id | 对象 ID |
| object_name | 对象名称，如统一座椅、竞品 Logo |
| object_type | 物体、Logo、海报、屏幕内容、车辆品牌 |
| check_mode | 必须出现、禁止出现、匹配风格、匹配内容 |
| aliases | 别名 |
| reference_images | 参考图片 |
| text_keywords | OCR 或品牌关键词 |
| visual_prompt | 开放词汇检测描述 |
| threshold | 相似度或置信阈值 |
| min_count/max_count | 数量要求 |
| applicable_zones | 适用区域 |
| status | 启用、停用 |

### 5.3 合规规则模板 Rule Template

规则模板用于复用合规判断逻辑。

示例：

1. “指定对象必须出现”
2. “禁止对象不得出现”
3. “屏幕内容需匹配参考图”
4. “指定区域内对象数量需满足范围”
5. “不得出现非授权品牌”

字段：

| 字段 | 说明 |
|---|---|
| rule_template_id | 模板 ID |
| name | 模板名称 |
| rule_type | 规则类型 |
| input_required | 必填输入 |
| output_event_type | 输出事件类型 |
| default_threshold | 默认阈值 |
| evidence_required | 是否必须证据 |
| supported_object_types | 支持对象类型 |

### 5.4 视觉合规订阅 Visual Compliance Subscription

视觉合规订阅是现有“应用订阅”的扩展配置，不新增主链路。

字段：

| 字段 | 说明 |
|---|---|
| subscription_id | 订阅 ID，复用现有订阅 |
| app_id | 门店视觉合规巡检应用 |
| object_pack_id | 对象包 |
| object_pack_version | 对象包版本 |
| rule_template_ids | 规则模板 |
| org_scope | 门店或区域 |
| camera_scope | 摄像头范围 |
| schedule | 布防时间 |
| evidence_policy | 截图、视频片段、检测框 |
| confidence_policy | 置信策略 |
| update_policy | 对象包更新策略 |

对象包更新策略：

| 策略 | 说明 | 适用场景 |
|---|---|---|
| 固定版本 | 订阅绑定对象包固定版本 | 审计要求强 |
| 跟随最新版 | 对象包更新后订阅自动使用新版 | 变化频繁 |
| 审批后更新 | 对象包更新后生成待确认计划 | 大多数企业客户 |

建议默认使用：**审批后更新**。

## 6. 功能设计

### 6.1 对话式创建视觉合规巡检

用户输入示例：

1. “帮我检查极狐门店里有没有按要求摆放统一座椅、立牌展架，电视是否播放指定广告，也要看有没有其他品牌汽车。”
2. “帮我检查 OPPO 门店里有没有其他品牌 Logo 或宣传海报。”
3. “下周开始每天营业时间巡检华东区所有门店的竞品物料露出。”

系统处理：

1. 识别意图：`VISUAL_COMPLIANCE_SUBSCRIPTION_CREATE`。
2. 识别行业场景：汽车展厅、手机门店。
3. 抽取对象：
   - 必须出现：统一座椅、立牌展架、指定广告图。
   - 禁止出现：其他品牌汽车、其他品牌 Logo、宣传海报。
4. 推荐对象包：
   - 如果已有对象包，推荐复用。
   - 如果没有对象包，生成对象包草稿。
5. 追问缺失信息：
   - 指定广告图片是否已上传？
   - 哪些品牌属于禁止品牌？
   - 巡检哪些门店和摄像头？
   - 是否只在营业时间检测？
6. 生成计划卡。
7. 用户确认。
8. 创建视觉合规订阅。

计划卡展示：

| 区域 | 内容 |
|---|---|
| 计划摘要 | 创建“门店视觉合规巡检”订阅 |
| 巡检对象 | 必须出现对象、禁止出现对象 |
| 参考素材 | 已上传/待上传 |
| 门店范围 | 区域、门店数 |
| 摄像头范围 | 推荐摄像头数、待确认摄像头 |
| 生效时间 | 布防时间、有效期 |
| 风险提示 | 未上传参考图、对象歧义、低置信需人工确认 |
| 操作 | 确认、补充对象、上传素材、打开订阅页 |

### 6.2 对象包管理

对象包管理面向租户管理员、区域运营、内部交付。

页面入口：

1. AI 助手计划卡中的“管理对象包”。
2. 应用订阅页中的“对象包配置”。
3. 独立工作台中的“视觉对象库”。
4. 结果详情中的“加入对象包/加入禁用对象”。

页面结构：

```text
对象包列表
  -> 对象包详情
    -> 必须出现对象
    -> 禁止出现对象
    -> 参考素材
    -> 同义词
    -> 匹配策略
    -> 版本记录
```

对象包列表字段：

| 字段 | 说明 |
|---|---|
| 对象包名称 | 极狐展厅标准物料对象包 |
| 场景 | 汽车展厅、手机门店 |
| 对象数量 | 必须对象、禁止对象数量 |
| 生效订阅数 | 当前使用该对象包的订阅数量 |
| 当前版本 | v1.0 |
| 状态 | 草稿、生效、停用 |
| 最近更新 | 更新时间 |
| 操作 | 查看、编辑、复制、停用 |

对象包详情能力：

1. 新增对象。
2. 删除对象。
3. 上传参考图片。
4. 批量导入品牌 Logo。
5. 设置对象别名。
6. 设置匹配阈值。
7. 预览检测效果。
8. 发布新版本。

### 6.3 对象快速变更

为了满足“用户随时变化想要查看的对象”，必须支持低成本变更。

对话示例：

1. “把小米 Logo 加入 OPPO 门店禁用品牌。”
2. “这次活动新增一个新的立牌样式，帮我加入极狐对象包。”
3. “不再检查电视广告图片，只检查座椅和立牌。”
4. “把其他品牌汽车的识别范围扩大到展厅所有摄像头。”

系统处理：

1. 识别意图：`OBJECT_PACK_UPDATE`。
2. 定位对象包。
3. 生成变更计划。
4. 展示影响订阅数量。
5. 用户确认。
6. 创建对象包新版本。
7. 根据更新策略：
   - 固定版本：不影响现有订阅。
   - 跟随最新版：自动影响订阅。
   - 审批后更新：生成订阅更新计划。

最短操作路径：

```text
用户说“加入 XX”
  -> 系统定位对象包
  -> 展示影响范围
  -> 用户确认
  -> 新版本生效
```

### 6.4 参考素材管理

参考素材用于提升识别准确性。

素材类型：

| 类型 | 示例 | 用途 |
|---|---|---|
| 物体参考图 | 座椅、展架 | 风格匹配、相似度 |
| Logo 图片 | OPPO、竞品 Logo | Logo 检测 |
| 海报图片 | 活动海报、竞品海报 | 海报匹配 |
| 屏幕截图 | 指定广告画面 | 电视内容检测 |
| 文本关键词 | 品牌名、活动名 | OCR 匹配 |
| 负样本 | 易误识别对象 | 降低误报 |

上传要求：

1. 支持图片上传。
2. 支持批量上传。
3. 支持给图片打标签。
4. 支持设置为正样本或负样本。
5. 支持从巡检结果一键加入样本。

### 6.5 摄像头推荐与区域配置

用户不应逐个理解哪些摄像头适合检测哪些对象。

系统根据点位推荐：

| 巡检对象 | 推荐摄像头点位 |
|---|---|
| 统一座椅 | 接待区、休息区、展厅全景 |
| 立牌展架 | 门口、展厅入口、主通道 |
| 电视广告 | 电视/大屏点位 |
| 其他品牌汽车 | 展厅全景、车辆展示区 |
| 其他品牌 Logo/海报 | 门店全景、墙面、柜台、海报区 |

推荐逻辑：

1. 优先使用摄像头点位标签。
2. 没有点位标签时，使用快照和多模态模型做候选推荐。
3. 推荐结果必须人工确认。
4. 用户可以选择“全部摄像头检测”，但系统提示成本和误报风险。

### 6.6 巡检结果输出

结果类型：

| 类型 | 说明 | 示例 |
|---|---|---|
| 缺失事件 | 必须对象未出现 | 未发现统一立牌 |
| 禁止出现事件 | 禁止对象出现 | 发现竞品 Logo |
| 风格不符事件 | 对象存在但与参考不匹配 | 座椅样式不一致 |
| 内容不符事件 | 屏幕/海报内容不匹配 | 电视未播放指定广告 |
| 待确认事件 | 置信度不足，需要人工确认 | 疑似竞品海报 |

结果卡字段：

| 字段 | 说明 |
|---|---|
| 事件类型 | 缺失、禁止出现、风格不符、内容不符 |
| 对象名称 | 统一座椅、竞品 Logo |
| 门店/摄像头 | 所属位置 |
| 发生时间 | 检测时间 |
| 证据截图 | 框选结果或全景截图 |
| 判断依据 | 命中的对象包、规则、参考素材 |
| 置信度 | 识别置信度 |
| 对象包版本 | 如 v1.2 |
| 处理状态 | 待确认、真问题、误报、忽略 |
| 操作 | 查看证据、反馈、加入样本、调整规则 |

证据要求：

1. 禁止出现事件必须有检测框。
2. 缺失事件必须展示对应摄像头的全景截图和检测区域。
3. 屏幕内容不符必须展示屏幕区域截图和参考图对比。
4. 风格不符必须展示当前截图和参考样式。

### 6.7 结果统计

统计维度：

1. 门店。
2. 区域。
3. 对象包。
4. 对象类型。
5. 规则类型。
6. 摄像头。
7. 时间。
8. 处理状态。

核心指标：

| 指标 | 说明 |
|---|---|
| 合规率 | 合规门店数 / 巡检门店数 |
| 问题门店数 | 存在不合规事件的门店数量 |
| 禁止对象出现次数 | 竞品 Logo、其他品牌车辆等出现次数 |
| 必须对象缺失次数 | 统一座椅、立牌等缺失次数 |
| 待确认事件数 | 低置信事件 |
| 误报率 | 误报事件 / 已处理事件 |
| 对象包覆盖率 | 已配置对象包的门店占比 |

对话问数示例：

1. “上周哪些极狐门店没有标准立牌？”
2. “OPPO 门店最近 7 天发现最多的竞品 Logo 是哪个？”
3. “按区域统计一下品牌露出违规率。”
4. “把所有电视广告不合规的截图导出来。”

## 7. 技术实现策略

### 7.1 不改变核心工作流

底层使用一个通用工作流模板：

```text
视频帧数据源
  -> 场景/区域过滤
  -> 开放词汇对象检测
  -> Logo/OCR/图片相似度工具
  -> 多模态大模型复核
  -> 规则引擎
  -> 事件输出
```

现有画布节点映射：

| 节点 | 用途 |
|---|---|
| 数据源节点：视频帧 | 定时抽帧 |
| 小模型能力节点 | 通用目标检测、开放词汇检测、Logo 候选 |
| 大模型能力节点 | 多模态复核、复杂内容判断 |
| 工具库节点 | 对象包检索、OCR、图片相似度、品牌库 |
| 结果输出 | 生成合规事件 |

客户看到的是“门店视觉合规巡检”能力模板，不需要看到底层节点。

### 7.2 检测策略

不同对象使用不同策略组合：

| 对象 | 检测策略 |
|---|---|
| 标准座椅、立牌 | 开放词汇检测 + 参考图相似度 + 多模态复核 |
| Logo | Logo 检测 + OCR + 图片相似度 |
| 海报 | OCR + 图片相似度 + 多模态复核 |
| 电视广告 | 屏幕区域检测 + 参考图相似度 + OCR |
| 其他品牌汽车 | 车辆检测 + 车标/车型识别 + 多模态复核 |

原则：

1. 不单独依赖大模型判断。
2. 先产生候选，再用规则和多模态复核。
3. 低置信进入待确认，不直接告警。
4. 所有判断必须绑定证据。

### 7.3 反幻觉与准确性治理

1. 模型不得编造对象，所有对象来自对象包。
2. 检测结果必须绑定截图、框选区域和规则。
3. 低置信不输出确定结论。
4. 缺失事件必须说明检测范围和时间。
5. 用户反馈误报后可加入负样本。
6. 对象包变更必须有版本记录。
7. 统计结果必须绑定查询条件。

### 7.4 对意图识别模块的改造说明

新增极狐和 OPPO 这类门店视觉合规场景后，当前意图识别模块不能只依赖原有通用意图。原有 `SUBSCRIPTION_CREATE`、`RESULT_QUERY`、`DATA_STATS`、`FEEDBACK_CREATE` 仍然保留，但需要扩展视觉合规子意图、槽位、词典和低置信追问机制。

总体判断：

| 模块 | 影响级别 | 结论 |
|---|---|---|
| 通用订阅创建意图 | 中 | 可复用，但需要细分视觉合规订阅创建 |
| 对象包创建/修改 | 高 | 当前通用订阅意图无法准确承接，需要新增写操作意图 |
| 参考素材补充 | 高 | 属于新型素材资产写操作，需要独立识别和权限控制 |
| 规则变更 | 中高 | 可能影响多个订阅，需要计划卡和审批 |
| 结果查询/统计 | 中 | 可作为结果查询和统计查询的视觉合规细分意图 |
| 反馈/badcase | 中 | 需要支持“加入正样本/负样本/调整规则” |

建议新增意图：

| 意图编码 | 名称 | 风险级别 | 触发示例 | 执行方式 |
|---|---|---|---|---|
| `VISUAL_COMPLIANCE_SUBSCRIPTION_CREATE` | 创建视觉合规订阅 | 高 | 帮我检查 OPPO 门店有没有其他品牌 Logo | 生成计划卡，确认后创建订阅 |
| `VISUAL_COMPLIANCE_SUBSCRIPTION_UPDATE` | 修改视觉合规订阅 | 高 | 把巡检范围扩大到华南区门店 | 展示影响范围，确认后更新 |
| `OBJECT_PACK_CREATE` | 创建对象包 | 中高 | 新建一个极狐展厅物料对象包 | 生成对象包草稿，确认后保存 |
| `OBJECT_PACK_UPDATE` | 修改对象包 | 高 | 把小米 Logo 加入 OPPO 禁用品牌 | 展示对象包版本和影响订阅，确认后发布新版 |
| `OBJECT_PACK_VERSION_APPLY` | 应用对象包版本 | 高 | 把新版对象包应用到现有订阅 | 生成订阅更新计划 |
| `REFERENCE_ASSET_ADD` | 添加参考素材 | 中 | 这张立牌是新版本，加入对象包 | 绑定对象和样本极性后入库 |
| `REFERENCE_ASSET_REMOVE` | 删除参考素材 | 中 | 去掉旧版广告图 | 展示影响对象和订阅，确认后删除或停用 |
| `VISUAL_RULE_UPDATE` | 修改视觉合规规则 | 高 | 电视广告低于 80% 相似度就告警 | 修改规则阈值，生成审计 |
| `VISUAL_COMPLIANCE_RESULT_QUERY` | 查询视觉合规结果 | 中 | 上周哪些门店出现了竞品 Logo | 走结果中心查询 |
| `VISUAL_COMPLIANCE_STATS_QUERY` | 查询视觉合规统计 | 中 | 按区域统计品牌露出违规率 | 走统计语义层 |
| `OBJECT_FEEDBACK_TO_SAMPLE` | 结果反馈转样本 | 中 | 这个是误报，加入负样本 | 写入 badcase 和对象包样本 |
| `CAMERA_RECOMMEND_FOR_OBJECTS` | 为对象推荐摄像头 | 中 | 看电视广告应该用哪些摄像头 | 输出候选点位，人工确认 |

需要新增槽位：

| 槽位 | 说明 | 示例 | 是否关键 |
|---|---|---|---|
| `visual_compliance_scene` | 巡检场景 | 汽车展厅、手机门店、柜台、海报区 | 是 |
| `object_pack_id` | 对象包 | 极狐展厅标准物料对象包 | 条件关键 |
| `object_pack_version` | 对象包版本 | v1.2 | 否 |
| `target_objects` | 必须出现对象 | 统一座椅、立牌展架 | 是 |
| `forbidden_objects` | 禁止出现对象 | 其他品牌 Logo、其他品牌汽车 | 是 |
| `object_type` | 对象类型 | Logo、海报、屏幕内容、车辆品牌 | 是 |
| `brand_scope` | 品牌范围 | vivo、华为、小米、其他汽车品牌 | 条件关键 |
| `reference_assets` | 参考素材 | 广告图、Logo 图、海报图 | 条件关键 |
| `check_mode` | 检查模式 | 必须出现、禁止出现、风格匹配、内容匹配 | 是 |

| `match_threshold` | 匹配阈值 | 0.75、80% | 否 |

| `object_pack_update_policy` | 版本更新策略 | 固定版本、跟随最新版、审批后更新 | 否 |
| `sample_polarity` | 样本极性 | 正样本、负样本 | 否 |

业务词典需要扩展：

| 词典 | 内容 | 用途 |
|---|---|---|
| 物料同义词 | 立牌、展架、易拉宝、海报、台卡、吊旗 | 对象抽取和实体归一 |
| 品牌词典 | 客户品牌、竞品品牌、授权品牌、禁用品牌 | 品牌消歧 |
| 场景词典 | 展厅、门店、柜台、电视区、海报区、休息区 | 摄像头推荐和区域定位 |

意图识别置信度策略：

| 场景 | 策略 |
|---|---|
| 高风险写操作置信度低于阈值 | 必须追问，不直接执行 |
| 对象包定位失败 | 结合租户、当前页面、最近订阅和对象名称召回候选 |
| 对象歧义 | 展示候选对象，要求用户选择 |
| 品牌范围不明确 | 区分“所有其他品牌”“指定竞品品牌”“非授权品牌” |
| 涉及多个订阅 | 计划卡展示影响订阅数和订阅清单摘要 |

### 7.5 Plan DSL 改造说明

视觉合规场景下，Plan DSL 需要支持对象包、参考素材、规则和版本策略的结构化表达。所有高风险写操作必须先生成计划卡，用户确认后执行。

新增 Plan action：

| action | 含义 | 风险级别 | 是否需要确认 |
|---|---|---|---|
| `visual_compliance.subscription.create` | 创建视觉合规订阅 | 高 | 是 |
| `visual_compliance.subscription.update` | 修改视觉合规订阅 | 高 | 是 |
| `object_pack.create` | 创建对象包 | 中高 | 是 |
| `object_pack.update` | 修改对象包 | 高 | 是 |
| `object_pack.apply_version` | 应用对象包新版本 | 高 | 是 |
| `reference_asset.add` | 添加参考素材 | 中 | 是 |
| `reference_asset.remove` | 删除或停用参考素材 | 中高 | 是 |
| `visual_rule.update` | 修改规则阈值或规则模板 | 高 | 是 |
| `sample.add_from_feedback` | 从反馈加入样本 | 中 | 可按权限配置 |
| `camera.recommend_for_objects` | 为对象推荐摄像头 | 低 | 否，推荐结果需人工确认 |

计划卡必须展示：

| 展示项 | 说明 |
|---|---|
| 意图类型 | 创建订阅、修改对象包、添加素材、调整规则 |
| 对象包 | 使用哪个对象包和版本 |
| 变更对象 | 新增、删除或修改了哪些对象 |
| 参考素材状态 | 已上传、缺失、素材需完善 |
| 影响订阅 | 对象包或规则修改会影响哪些订阅 |
| 门店/摄像头范围 | 生效组织、门店和摄像头 |
| 风险提示 | 缺少参考图、对象歧义、低置信、成本增加 |
| 执行结果 | 成功、部分成功、失败及失败原因 |

Plan DSL 执行约束：

1. 不允许大模型直接执行对象包或订阅写操作，必须落到明确 action。
2. 写操作必须带 `tenant_id`、`operator_id`、`idempotency_key` 和审计上下文。
3. 修改对象包时默认创建新版本，不覆盖历史版本。
4. 应用对象包新版本时必须遵循订阅的 `update_policy`。
5. 执行失败时返回可恢复错误，例如缺素材、无权限、对象包不存在、订阅冲突。

### 7.6 Skill 链路改造说明

| 12 | `feedback_to_sample` | 用户反馈、事件证据 | 正/负样本、badcase | 复用增强 |

| `object_pack_id` | 对象包 ID |

| `camera_ids` | 摄像头 |

Skill 输出建议：

| 字段 | 说明 |
|---|---|
| `event_type` | 缺失、禁止出现、风格不符、内容不符、待确认 |
| `object_id` | 命中的对象 |

| `rule_id` | 命中规则 |
| `judgement` | 合规、不合规、待确认 |

| `evidence_assets` | 截图、框选图、对比图 |
| `bounding_boxes` | 检测框 |

| `requires_human_review` | 是否需要人工确认 |

Skill 反幻觉约束：

1. Skill 只能判断对象包中定义的对象、品牌和规则。
2. 多模态模型输出必须使用结构化 schema，不输出自由文本结论作为最终判定。
3. 大模型只做候选复核和解释生成，最终事件由规则引擎输出。
4. 不存在证据截图或检测区域时，不允许输出确定违规事件。
5. 低置信、遮挡、模糊、跨品牌歧义必须进入待确认。
6. 每条事件必须携带对象包版本、规则 ID、模型版本和 trace ID。

需要新增或扩展的数据对象：

| 数据对象 | 说明 | 归属模块 |
|---|---|---|

| `object_definition` | 对象定义 | 视觉对象库 |

新增结果事件类型：

| 事件类型 | 说明 |
|---|---|
| `VISUAL_REQUIRED_OBJECT_MISSING` | 必须对象缺失 |
| `VISUAL_FORBIDDEN_OBJECT_FOUND` | 禁止对象出现 |
| `VISUAL_STYLE_MISMATCH` | 风格不匹配 |
| `VISUAL_CONTENT_MISMATCH` | 屏幕或海报内容不匹配 |

结果状态机：

```text
待确认
  -> 真问题
  -> 误报
  -> 忽略
  -> 已整改
  -> 已关闭
```

状态约束：

1. 低置信事件默认进入“待确认”。
2. 用户标记“误报”后，可以加入负样本或生成规则调整计划。
3. 用户标记“真问题”后，可以进入整改流或导出报表。
4. “已整改”必须保留原始证据和复检证据。

### 7.8 评测集与质量门禁

| 样本类型 | 示例 |
|---|---|
| 创建订阅 | 帮我检查 OPPO 门店有没有其他品牌 Logo |
| 修改对象包 | 把小米 Logo 加入禁用品牌 |
| 添加参考素材 | 这张立牌是新版本，加入极狐对象包 |
| 修改规则 | 电视广告低于 80% 相似度就告警 |
| 查询结果 | 上周哪些门店发现竞品海报 |
| 查询统计 | 按区域统计品牌露出违规率 |
| 反馈转样本 | 这个不是竞品 Logo，加入负样本 |

Skill 评测集至少覆盖：

| 样本类型 | 说明 |
|---|---|
| 正样本 | 标准座椅、标准立牌、指定广告、竞品 Logo |
| 负样本 | 相似但非目标对象、模糊 Logo、非竞品海报 |
| 缺失样本 | 目标对象不在画面中 |
| 遮挡样本 | 目标对象部分遮挡 |
| 屏幕反光样本 | 电视广告受反光影响 |
| 多品牌混合样本 | 同画面出现多个品牌 |

P0 质量门禁：

1. 高风险写操作意图必须能正确识别并生成计划卡。
2. 意图低置信时必须追问，不允许静默执行。
3. Skill 输出必须包含证据、规则、对象包版本和模型版本。
4. 无证据或低置信结果不能进入确定违规。
5. 评测集回归失败时，不允许发布新的对象包模板或 Skill 版本。

## 9. 客户场景示例

### 9.1 极狐：展厅物料与品牌合规

对象包：极狐展厅标准物料对象包。

对象配置：

| 对象 | 类型 | 规则 | 检测策略 |
|---|---|---|---|
| 统一风格座椅 | 标准物体 | 必须出现、风格匹配 | 开放词汇检测 + 参考图相似度 |
| 统一立牌展架 | 标准物料 | 必须出现、位置建议 | 检测 + 参考图 |
| 指定电视广告 | 屏幕内容 | 内容匹配 | 屏幕检测 + 图片相似度 |
| 其他品牌汽车 | 禁止对象 | 禁止出现 | 车辆检测 + 车标识别 + 多模态复核 |

对话创建示例：

> 帮我给华东区极狐门店创建展厅物料合规巡检，检查统一座椅、立牌、电视广告，以及是否有其他品牌汽车，营业时间内巡检。

系统输出：

1. 推荐“极狐展厅标准物料对象包”。
2. 提示上传电视广告参考图。
3. 推荐展厅全景、入口、电视区域摄像头。
4. 生成订阅计划卡。

|---|---|---|---|

| 华为 Logo | 禁止品牌 | 禁止出现 | Logo 检测 + OCR |
| 小米 Logo | 禁止品牌 | 禁止出现 | Logo 检测 + OCR |
| 竞品宣传海报 | 禁止物料 | 禁止出现 | OCR + 图片相似度 + 多模态复核 |

## 11. 验收标准

### 11.1 通用性验收

1. 同一“门店视觉合规巡检”能力可以同时支持极狐和 OPPO。
2. 不需要为不同客户新增独立工作流。
3. 新客户只需新建对象包和规则模板即可复用能力。

### 11.2 灵活性验收

1. 用户可以通过对话新增或删除巡检对象。
2. 对象包更新后生成新版本。
3. 对象包变更能展示影响订阅范围。
4. 用户可以选择是否让现有订阅使用新版本。

### 11.3 操作路径验收

1. 用户通过对话创建视觉合规订阅不超过 4 个关键确认步骤。
2. 已有对象包时，创建订阅只需选择对象包、门店范围和时间。
3. 修改对象不需要进入工作流画布。

### 11.4 结果可信验收

1. 禁止对象出现事件必须有检测框。
2. 缺失事件必须有检测范围截图。
3. 结果必须展示对象包版本和命中规则。
4. 低置信事件进入待确认。
5. 用户反馈误报后可进入 badcase。

### 11.5 架构一致性验收

1. 复用现有应用订阅链路。
2. 复用现有结果中心。
3. 复用现有对话入口和 Plan DSL。
4. 复用现有工作流画布作为高级配置，不强制客户使用。

### 11.6 意图识别验收

1. 能正确识别视觉合规订阅创建、订阅修改、对象包创建、对象包修改、参考素材添加、规则调整、结果查询、统计查询和反馈转样本。
2. 高风险写操作必须生成计划卡，不允许直接静默执行。
3. 对象包定位失败时必须展示候选或追问。
4. 品牌范围不明确时必须追问“全部其他品牌、指定竞品品牌、非授权品牌”。
5. 低置信意图不得执行写操作。

### 11.7 Skill 链路验收

1. 系统只需要一个通用 `visual_compliance_inspection` Skill，不为极狐、OPPO 建客户专属 Skill。
2. Skill 能根据对象包版本加载对象、规则、参考素材和品牌范围。
3. Skill 输出必须包含事件类型、对象、规则、置信度、证据、对象包版本、模型版本和 trace ID。
4. 大模型复核结果不能直接作为最终事件，最终事件必须由规则引擎输出。
5. 无证据、低置信或对象不在对象包内时，结果必须进入待确认或不输出确定违规。

### 11.8 Plan DSL 与审计验收

1. `object_pack.update`、`visual_rule.update`、`object_pack.apply_version` 等高风险 action 必须可审计。
2. 修改对象包必须生成新版本。
3. 计划卡必须展示影响订阅范围。
4. 订阅应用对象包新版本时必须遵循 `update_policy`。
5. 重试写操作必须通过 `idempotency_key` 保证幂等。

## 12. 风险与应对

| 风险 | 表现 | 应对 |
|---|---|---|
| 视觉对象变化大 | 不同门店物料样式不同 | 对象包支持多参考图和负样本 |
| Logo 太小或模糊 | 摄像头距离远，识别难 | 推荐摄像头点位，低置信待确认 |
| 缺失判断误报 | 画面角度没覆盖目标区域 | 必须展示检测范围，支持摄像头推荐和区域标定 |
| 屏幕内容反光 | 电视画面识别不准 | 屏幕区域检测 + 多帧抽样 |
| 其他品牌汽车识别难 | 车标不可见 | 车辆检测 + 车标/OCR/多模态复核，不确定进入待确认 |
| 用户频繁改对象 | 订阅稳定性受影响 | 对象包版本和审批后更新策略 |
| 大模型幻觉 | 编造对象或品牌 | 对象只能来自对象包和品牌库 |
| 意图识别不准 | 把对象包变更误识别为普通查询或订阅 | 新增视觉合规意图、槽位、评测集和低置信追问 |
| 对象包定位失败 | 用户说“加入新立牌”但未说明对象包 | 结合租户、页面上下文、最近订阅召回候选，必要时追问 |
| Skill 工具误用 | Logo、OCR、图片相似度调用顺序不稳定 | 固化通用 Skill 模板和工具 allowlist |
| Plan DSL 风险外溢 | 修改对象包影响多个订阅 | 计划卡展示影响范围，默认审批后更新 |
| 评测缺失 | 新增对象后效果不可控 | P0 建设意图评测集和 Skill 评测集，发布前回归 |

5. 门店视觉合规巡检应用模板。
6. 对话创建订阅。
7. 禁止出现对象检测。
8. 必须出现对象检测。
9. 结果证据卡。

第二优先级：

1. 屏幕内容匹配。
2. 其他品牌车辆识别。
3. 摄像头点位推荐。
4. 对象包版本影响分析。
5. 结果反馈转样本闭环增强。

## 14. 总结

本方案不为极狐和 OPPO 分别创建定制功能，而是抽象出统一的“门店视觉合规巡检”能力。

关键产品设计是：

1. 用 **对象包** 解决“用户想看什么对象”的灵活变化。
2. 用 **规则模板** 解决“如何判断合规”的通用性。
3. 用 **应用订阅** 复用当前产品链路。
4. 用 **对话入口 + Plan DSL** 降低操作成本。
5. 用 **证据化结果 + badcase 反馈** 保证可信和可进化。
6. 用 **视觉合规意图 + 通用 Skill** 承接极狐、OPPO 和后续更多行业场景。

这样既能快速响应极狐和 OPPO 的需求，也能沉淀为面向更多连锁门店客户的标准化产品能力。
