# 多轮对话上下文承接优化方案（2026-08-27）

> 状态：已由 [V2 跨门店范围版](./CONVERSATION_CONTEXT_CONTINUATION_OPTIMIZATION_PLAN_V2_2026-08-27.md) 替代。V1 将门店误设为上下文硬边界，不适用于“页面停留在 A 店、对话查询 B 店”以及多门店巡检；仅保留作问题分析记录。

## 1. 目标与边界

目标是在同一用户、同一租户、同一会话内，让用户可以自然地承接上一轮任务。例如上一轮已分析门店画面，下一轮输入“再帮我找一个灰色的沙发”时，系统应继续在上一轮已授权的镜头/证据范围内执行视觉检索，而不是跳转为通用的沙发购买建议。

本方案不跨会话、跨用户、跨租户或跨门店继承上下文；不向开放问答、公开检索或前端暴露巡检图片、供应商签名 URL、访问令牌或内部证据路径。

## 2. 已确认的断点

复现输入：`在帮我找一个灰色的沙发`（“再”误输入为“在”也应被容错）。

| 链路 | 当前行为 | 影响 |
| --- | --- | --- |
| 视觉续问识别 | `OnlineInspectionAgent._references_previous_visual` 只识别“上面/刚才/这个画面”等有限表述；该输入返回 `false` | 未被标识为承接上一轮画面 |
| 路由优先级 | `handle_message` 先尝试 `_open_question_response`，视觉意图解析在其后 | 开放问答以 `OPEN_QA`、0.72 置信度接管，输出购买建议 |
| 已归档图像再消费 | 上一轮的 `visual_context` 被归档为本地 `/api/online-snapshot-evidence/...`；`_safe_media_url` 只接受 http/https/webrtc/artc | 即使识别到视觉续问，也无法取回已归档证据 |
| 泛化能力 | `_effective_visual_question` 的目标继承依赖垃圾、接待等固定词 | 沙发、背包款式、陈列品颜色等动态对象无法可靠继承 |
| 历史表达 | `open_qa_history` 提供消息文本，但没有可执行、受权限约束的跨轮任务状态 | 业务域只能各自用局部规则“猜”上文 |

补充风险：归档代理 URL 即使被允许传入，远程 VLM/OVD 也不能可靠访问相对路径；正确做法是后端按证据 ID 读取受控归档字节，在模型调用前临时编码为数据 URL，而不是把代理 URL 交给模型。

## 3. 目标架构

```text
当前输入 + 当前会话最近活动状态
        │
        ▼
ContinuationResolver（结构化决策；无副作用）
  ├─ CONTINUE_VISUAL  → EvidenceResolver → VLM / OVD
  ├─ CONTINUE_OPEN_QA → 安全的开放问答摘要
  ├─ CONTINUE_PLAN    → 既有 Plan 槽位补全
  ├─ NEW_TURN         → 常规 DomainRouter / IntentRouter
  └─ CLARIFY          → 显式询问“沿用上一轮画面还是发起新查询？”
```

路由优先级固定为：显式模式锁（`OPEN_QA` / `INSPECTION`）与安全接入/写操作门禁 → 有效的待确认 Plan → 高置信续问决策 → 常规域路由 → 低置信澄清。这样既不让开放问答抢走巡检续问，也不允许巡检上下文泄漏到开放问答。

## 4. P0 实现方案

### 4.1 新增受控会话状态

新增 `conversation_contexts`（或等价的专用持久化对象），而不是将运行所需状态塞入普通消息文本。建议字段：

| 字段 | 说明 |
| --- | --- |
| `context_id`、`conversation_id`、`tenant_id`、`user_id` | 归属与权限边界 |
| `domain`、`state`、`version` | `VISUAL` / `OPEN_QA` / `PLAN` 等受控状态机 |
| `effective_query`、`scope_json` | 已实际执行的问题、门店/镜头范围和时间语义 |
| `evidence_ids_json` | 仅保存归档证据 ID，不保存供应商 URL、访问令牌或图片 Base64 |
| `summary_json` | 最小化的结构化结论、槽位和可继续动作 |
| `created_at`、`expires_at`、`superseded_at` | 时效、覆盖和清理 |

视觉状态只保留最近一个仍有效的状态。用户切换租户/门店、会话关闭、证据过期或明确说“新问题/不要沿用”时立即失效。建议默认上下文 TTL 为 30 分钟；静态快照的“同一张图”复用仅在显式指代或短时窗口内发生，直播上下文一律重新抓取同一已授权镜头的当前帧。

### 4.2 续问语义决策器

新增 `ContinuationResolver.resolve(current_text, active_contexts, mode_override)`，在 `DomainRouter` 和 `_open_question_response` 之前运行。输出严格 Schema：

```json
{
  "decision": "CONTINUE_VISUAL|CONTINUE_OPEN_QA|CONTINUE_PLAN|NEW_TURN|CLARIFY",
  "confidence": 0.0,
  "context_id": "ctx_...",
  "effective_query": "画面中是否有灰色沙发？",
  "evidence_mode": "REUSE|REFRESH|NONE",
  "reason_code": "VISUAL_FOLLOW_UP"
}
```

决策器采用两层方式：

1. 明确指代的轻量规则快速命中，例如“再帮我/继续/同一镜头/这张图/换一个对象/其中一个”；对“再/在”这类单字输入误差做归一，但不凭一个普通名词强行继承。
2. 其余候选交给已有结构化模型做**续问关系判断**，输入仅含当前文本、最近活动状态的领域/有效问题/门店镜头摘要和时间，不含图片、URL、令牌或其他会话内容。模型只可在受限枚举中选择决策并改写 query，不能自行指定门店、镜头、证据或工具。

`confidence >= 0.85` 执行承接；`0.60–0.85` 返回一次明确澄清；低于阈值走新问题路由。模型不可用时，只处理明确指代，其他情况澄清，不退化为错误的开放问答。

### 4.3 证据再消费与模型输入

新增服务端 `EvidenceResolver`：按 `context_id + evidence_id + tenant_id + user_id` 查询已归档的 `online_snapshot_evidence`，校验文件根目录、MIME、大小和 TTL 后读取图像字节，临时生成 `data:image/...;base64,...` 供本轮 VLM/OVD 使用。

关键约束：

- 前端消息序列化继续隐藏 `visual_context`；API 不返回内部状态、证据路径或数据 URL。
- 归档记录中不持久化第三方签名 URL；上下文表只保存 `evidence_id`。
- 视觉模型与 OVD 只接收本轮经验证的图像字节；开放问答与公开检索绝不接收巡检图像或视觉结论原文。
- `REUSE` 使用同一归档帧；`REFRESH` 只能调用状态中记录且仍有权限的相同镜头；失败返回 `UNCERTAIN/BLOCKED`，不能转成“未发现”。

### 4.4 视觉 query 泛化

当决策为 `CONTINUE_VISUAL` 时，直接采用 `effective_query`，例如“画面中是否有灰色沙发？”，而非依赖垃圾、接待、工服等固定词表。既有动态 OVD 提示词规划器会从该 query 提取 `sofa` 等最小对象类别，后续仍由 VLM 根据颜色、材质、关系、款式等完整语义验证。

### 4.5 用户可见性与可控性

回复和执行轨迹增加简洁说明：`已承接上一轮：门店 X / 镜头 Y / 快照时间 T（复用快照或已刷新）`。输入框上方显示一次性上下文条，用户可以点击“使用新画面”或“清除上下文”。出现中置信度时，不直接猜测，询问：`你是想在刚才的镜头中继续查找灰色沙发，还是需要通用选购建议？`

## 5. 分期与验收

| 阶段 | 内容 | 放行标准 |
| --- | --- | --- |
| P0-1 | 会话状态表、EvidenceResolver、视觉续问决策与路由优先级修正 | 截图场景稳定进入 `ANALYZE_VISUAL`，不调用 `OPEN_QA/web.search` |
| P0-2 | 结构化语义续问、改写 query、前端上下文条与清除动作 | 动态对象、颜色、款式、位置等续问正确承接；中置信度只澄清 |
| P1 | 开放问答/Research 的摘要化上下文和指标面板 | 同域开放问答能承接目的地/日期/偏好，且不读取巡检上下文 |

必须新增的回归用例：

1. 上一轮视觉检查后，“再/在帮我找一个灰色的沙发”进入视觉链路，使用原镜头证据。
2. 背包款式、衣服颜色、桌上水瓶、出口标识等任意对象/属性续问，不依赖固定词表。
3. “这张图里还有吗”复用静态证据；“现在再看一下”刷新同镜头。
4. 用户明确问“给我一份灰色沙发选购建议”进入开放问答，不复用巡检图像。
5. `OPEN_QA`/`INSPECTION` 显式模式、租户/门店切换、会话关闭、TTL 到期均不能错误承接。
6. 证据 ID 篡改、跨用户/租户、证据文件缺失、过期及模型失败均被拒绝或标记 `UNCERTAIN`，不得泄露路径/令牌或给出否定结论。
7. 消息时间相同的历史读取按稳定序号排序，确保用户/助手轮次顺序可预测。
8. 全量回归保留既有点位消歧、Plan 槽位补全、Open QA 连续旅行问答、公开检索隔离与视觉 OVD 用例。

上线观测指标：续问命中率、误承接率、澄清率、视觉续问进入 OPEN_QA 的次数（目标为 0）、证据复用/刷新成功率、跨域/越权拒绝次数和 P95 延迟。

## 6. 非目标

- 不把历史对话全文或巡检图片直接拼进所有模型请求。
- 不通过扩展关键词列表来替代语义判断。
- 不跨会话自动“记住”门店、人员、视频或视觉结论。
- 不让 OVD 检测框单独决定“存在/不存在”；仍保留 VLM 语义核验和证据门禁。
